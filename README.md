# TYAGA Server

Backend для **TYAGA** — одиночной игры с соревновательным аспектом в виде глобального leaderboard.

Этот репозиторий содержит серверную часть проекта: авторизацию, игроков, прогрессию, скины, достижения, сессии и данные для будущего leaderboard.

Сама игра находится за пределами этого репозитория.

## ✨ Что уже работает

### 👤 Игроки

У каждого игрока есть собственная постоянная запись в базе данных.

```text
Player
├── ID
├── Очки
├── Дата создания
└── Профиль
    ├── Никнейм
    └── Аватар
```

Данные авторизации хранятся отдельно от самого игрока, поэтому аккаунт не привязан к одному конкретному способу входа.

---

### 🔑 Авторизация

Система авторизации строится вокруг единого аккаунта игрока и нескольких возможных способов входа.

На данный момент полностью работает Telegram WebApp и браузерный Web Auth flow. Архитектура авторизации подготовлена для дальнейшего подключения Telegram Login Widget и Twitch.

```text
                         TYAGA AUTH
                             │
                ┌────────────┼────────────┐
                │            │            │
                ▼            ▼            ▼
          📱 Telegram     🌐 Web        🎮 Game
             WebApp        Auth         Client
                │            │            │
                └────────────┼────────────┘
                             ▼
                         👤 Player
                             │
                             ▼
                        🔐 Session
```

---

### 📱 Telegram WebApp

Telegram Mini App использует серверную проверку `initData`.

```text
Telegram WebApp
       │
       │ initData
       ▼
┌─────────────────┐
│    TYAGA API    │
│                 │
│ HMAC validation │
│ auth_date       │
│ Telegram user   │
└────────┬────────┘
         │
         ▼
      Игрок
         │
         ▼
      Сессия
```

После успешной авторизации сервер:

1. проверяет Telegram `initData`;
2. находит или создаёт игрока;
3. связывает Telegram identity с игроком;
4. создаёт серверную сессию;
5. возвращает данные игрока и токен сессии.

### 🌐 Web Auth

Для браузерной авторизации реализован отдельный flow.

```text
/auth
   │
   ├── Telegram
   │      │
   │      ▼
   │   /telegram
   │      │
   │      ├── 📱 Telegram Bot
   │      │
   │      └── 🌐 Login Widget
   │
   └── Twitch
          │
          └── 🚧 В разработке
```

Публичные страницы:

```text
https://auth.tyaga-game.ru/
https://auth.tyaga-game.ru/telegram
```

Telegram Web Auth flow уже доступен через публичный HTTPS-домен и протестирован на нескольких устройствах.

Страница `/telegram` предоставляет выбор способа входа через Telegram. Telegram Bot flow уже подключён к публичной странице, а Telegram Login Widget подготовлен для дальнейшей реализации.

### ⭐ Очки

У каждого игрока есть постоянный баланс очков.

Очки являются основой будущей системы прогрессии и соревновательного leaderboard.

---

### 🎨 Скины

На сервере реализована отдельная система каталога скинов и владения ими игроками.

```text
Skins
├── ID
├── Название
├── Цена
└── Secret flag

        │
        ▼

Player skins
└── Игрок → Скин
```

Каталог скинов отделён от данных конкретных игроков.

---

### 🏆 Достижения

Для достижений существует отдельная структура в базе данных и система условий.

```text
Achievement
├── ID
├── Название
├── Описание
└── Условия
```

Это позволяет развивать систему достижений без необходимости превращать клиент игры в источник истины.

---

### 🔐 Сессии

Авторизованные игроки работают через серверные сессии.

Для одного игрока одновременно может существовать только **одна активная сессия**.

```text
Игрок
  │
  └── Активная сессия
          │
          └── Token
```

Токены сессий не хранятся в базе данных в открытом виде — сервер работает с их SHA-256 хешами.

Срок действия сессии настраивается через `AUTH_SESSION_DAYS`.

## 🌐 Архитектура

Публичная инфраструктура построена вокруг отдельного VPS и собственного сервера Theseus.

```text
                         Интернет
                            │
                            ▼
                    ┌───────────────┐
                    │      VPS      │
                    │               │
                    │     Nginx     │
                    │ HTTPS / TLS   │
                    └───────┬───────┘
                            │
                     Reverse Tunnel
                            │
                            ▼
                    ┌───────────────┐
                    │    Theseus    │
                    │               │
                    │   Fastify     │
                    │    Node.js    │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │  PostgreSQL   │
                    └───────────────┘
```

Theseus используется как основной сервер приложения и базы данных.

VPS используется как публичная точка входа. Nginx принимает HTTPS-запросы и передаёт их через reverse tunnel на Theseus.

Это позволяет не выставлять сам сервер Theseus напрямую в интернет и при этом использовать собственные домены:

```text
https://api.tyaga-game.ru
https://auth.tyaga-game.ru
https://www.tyaga-game.ru
```

### API

Основной API доступен через:

```text
https://api.tyaga-game.ru
```

Например:

```text
GET /health
```

возвращает состояние сервера и базы данных.

## 🎯 Задача сервера

Backend является **источником истины** для данных игрока.

```text
                       TYAGA
                         │
                         ▼
                   ┌───────────┐
                   │   Игрок   │
                   └─────┬─────┘
                         │
          ┌──────────────┼──────────────┐
          │              │              │
          ▼              ▼              ▼
      ⭐ Очки         🎨 Скины      🏆 Достижения
          │              │              │
          └──────────────┼──────────────┘
                         │
                         ▼
                    🏆 Leaderboard
```

Игра отвечает за игровой процесс.

Сервер отвечает за то, **что происходит с данными игрока после игры и между сессиями**.

Клиент не должен самостоятельно определять или хранить авторитетные значения прогресса.
